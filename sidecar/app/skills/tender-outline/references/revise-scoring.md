# 清理②：评分对齐（修订②，原则从老流水线逐字保留）

基于 `out/analysis/evaluation.md` 的 **SCORE 评分标准清单**，对当前目录做修订，
使目录与评分体系对齐——评分项是评委打分的直接依据，目录必须让每个评分维度
有语义贴切的落点。

**跳过条件**：evaluation.md 无 SCORE 条目（向用户声明后跳过）。

## 可以做的修订

1. **查漏补缺**：评分标准中的每一项评分维度，目录里都应有语义贴切的对应章节；
   缺失的补上相应 L2/L3。
2. **覆盖要点**：若某评分要点提示了具体子内容（如「运维流程」「实施计划」
   「业务人员指导」），确保对应章节覆盖它。
3. **核心项置顶**：分值高的核心评分维度对应的章节，在不破坏逻辑流的前提下
   尽量前置（评委阅读疲劳是真实的）。

## 禁止与边界

4. **排除程序性条款**：封装、递交、截止时间、废标项、格式/装订/签章、合同签订及转让、
   联合体、保证金等属于招标流程/程序性条款，不进目录。
5. **只补缺/升级/改名，不瞎加**无依据章节；**已存在的合理章节不要删**。
6. **保持格式**：每行 `- ` 开头 + 无编号 + 真实缩进。

## 操作方式

读当前 `## 目录` 与 SCORE 清单 → 逐项核对评分维度的落点 → 新增/升级节点补
`来源标注 :: SCORE-xx`（可与已有 REQ/MAND 并挂）与 `## 目录说明` 行（概述里写清
该章如何回扣评分要点）→ 保持其余内容原样。
