# 来源标注与目录说明格式（assemble 的机器输入）

## 来源标注（`## 来源标注` 段，覆盖**有来源**的全部节点）

```
- <目录节点标题（与目录逐字一致，含括号与附件号）> :: <来源ID>[, <来源ID>]
```

- 来源 ID 语义：`MAND-xx` = 招标文件规定的必须章节；`TPL-xx` = 招标方给出的模板/格式；
  `REQ-xx` = 业务/技术要求；`SCORE-xx` = 评分标准维度。
- **只引用 analysis 产物里已有的编号**（编号=清单行序，REQ-01 是 requirements-business
  表的第 1 行……）；数字两位零填充（写 `MAND-01` 不写 `MAND-1`）。
- 一个节点可对应多个来源 ID；**无来源的纯过渡/兜底章不写该行**。
- 标题必须与目录树逐字一致（含括号与附件号），否则 assemble 挂不上 lineage
  （只做包含匹配兜底，不保证命中）。

## 目录说明（`## 目录说明` 段，全部有来源节点）

```
- <目录节点标题（逐字一致）> :: 交付形态=<枚举> | 归位理由=<一句话> | 理由来源=<来源ID,来源ID> | 概述=<1~2句话>
```

- `交付形态` 枚举：**正文编写 / 模板或附件填充 / 混合 / 目录容器 / 待核验**
  （判断不了用「待核验」，不得编造）。表格/索引/清单/填表类节点（评标索引表、
  分项报价表、格式化承诺函等）标「模板或附件填充」——按招标格式填表，
  不写散文正文。
- `归位理由` 只能基于该节点来源标注里已有的来源 ID 作答。
- `理由来源` 必须是该节点来源标注 ID 的子集，无则留空。
- `概述` 1~2 句说明该节点交付什么；**不写我方材料、不写具体写作步骤**；
  相关待澄清项在概述末尾加「⚠待澄清：…」。
- 无对应来源的节点可省略本行。

## 同步维护规则

清理道造成节点增/删/改名时：新增→立即补两段标注；删除→移除两段标注行；
合并→保留节点的来源 ID 取被并节点并集；改名→两段标注的标题同步改。
