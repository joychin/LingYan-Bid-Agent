# 清理③：走查定稿（修订③，原则从老流水线逐字保留）

以严谨的标书审核专家身份，对当前目录做**最后的清理定稿**。

## 清理动作

- **删除重复条目**：同名或同义的章节只保留一个。
- **合并近似**：同一主题被拆成多个实质相同的章节，合并为一个。
- **删除不合理条目**：
  - 明显不属于标书正文的条目；
  - 来源原文明确标注「**无需装订 / 现场携带 / 无需上交 / 电子版单独提交 / 谈判现场使用 /
    自行打印**」等装订属性的条目（此类材料属于独立递交，不在装订正文中）——
    **删除前回招标原文核实**（优先主文件；先读 `out/parse/<文件名>/<文件名>.outline.json`
    按行号取区段，禁止整读全文）；与之并列的「装订至文件中」的同类条目（如首次报价表）不受影响。
- **优化兄弟章节顺序（逻辑流）**：在不增删、不改名、不跨父章节的前提下，允许并应当
  调整同一父章节下兄弟章节的先后次序，使其符合「叙述/逻辑依赖」顺序：先写铺垫与
  被依赖的内容（如 项目/需求分析、现状调研、目标与规范），再写依赖它的核心内容
  （如 建设方案、设计方案、实施计划），最后写收尾内容（如 测试验证、成果交付、运维、
  保障措施）。不要把分析/调研/目标类章节排到它本应前置引导的方案/设计类章节之后。
- **同主体连续排布**：同一主体或同一交付物的多个章节应连续相邻，不要被无关章节隔开
  （例如围绕同一系统的「总体方案」与「详细设计方案」应紧邻）。

## 禁止

- 不要新增章节、不要改动合理章节的名称、不要添加编号、不要跨父章节移动。
- 层级格式严格遵守：每行 `- ` 开头，子章节相对父章节缩进 2 空格。

## 抽查核实（出处引用键回读）

走查中对存疑的来源标注做抽查：按该条目出处里的行号区间（L起-L止）回读原文区段，
核对章节确在其列、表述与登记表一致；发现对不上（行号指空/内容不符）→ 恢复正确出处
或删除该节点，并在汇报中说明。抽查不少于 3 条（不足 3 条全查）。

## 操作方式

读当前 `## 目录` → 逐项走查上述动作 → 被删/被合并的节点**同步移除**其 `## 来源标注`
与 `## 目录说明` 行（被合并的保留来源 ID 的并集挂到保留节点上）→ 输出走查后的干净目录。
