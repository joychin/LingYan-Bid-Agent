# 响应文件正文编写（tender-body）

## 概述

先读 `skills/_shared/response-guidelines.md`（用户回复规范）。写作依据 = 任务内
当前投标目录（read_artifact 按契约读取——每节带来源 ID（MAND/TPL/REQ/SCORE）与
交付形态）。正文 = 逐节回应的展开：招标要求逐条覆盖、我方事实可溯、方案思路是
唯一真正生成的内容；**承诺类数字（工期/人员/服务承诺/报价口径）只出自用户拍板的
清单，禁止自造**。证据纪律先读 `skills/_shared/evidence-rules.md`。

正文产物在当前任务 `work/body/` 下：**每节一个 .docx**（docx 直出——写作与
修订全部经 docx 工具族，模型不直接写 docx 二进制）；写作指引与关键事实承诺
清单仍是 .md（共享文件，主线程维护）。

## 执行流程

### 第 0 步：查现状

调用 `check_pipeline_state`（无参数），按 `[body]` 段事实裁决：

- 无目录产物 → 引导用户先走 tender-outline，不凭空编目录；
- `[body]` 报「文件无对应目录节点」或「目录产物更新晚于正文」→ 目录已改版：
  向用户点名失配节，由用户裁决重写哪些（用户没裁决前不动这些节）；
- `[body]` 已写若干节、且用户要求重写/重新生成 → **先 ask_human 问范围**，不默认
  全量重写（已写内容是有效产出，全量重写浪费 token 与时间）：options=全部重写；
  只重写我指定的章节（在补充说明里写明）；只重写自查不通过的节（推荐）。
  按用户圈定的范围执行——**重写已存在的节时 docx_section_create 传
  replace=true**（旧版自动入恢复点栈，直接建档会被拒）；
- 指引已生成且用户没让重写 → 沿用现有指引，继续写未写的节。

### 第 1 步：开工（先指引、后承诺）

1. 生成 `work/body/写作指引.md`——格式契约见 `references/guide-format.md`：逐节判
   写作模式（素材修订/格式跟随/推理撰写），search_references 粗匹配素材（素材列
   记块 id，确无素材标【缺】）。缺料即备料对账，向用户点名缺什么。
2. `validate_body(section="body/写作指引.md")` 自查通过后，ask_human 请用户确认
   指引——**question 之外传 `guide_path="body/写作指引.md"`**（前端会在提问卡上
   渲染「打开指引」按钮，一键打开查看修改）；options=确认，按指引开写；重新生成
   指引。
3. ask_human 收承诺值：工期、人员配置原则、服务承诺、报价口径等用户未提供的
   逐项问（一次问全，不逐节打断）；把回答落 `work/body/关键事实与承诺.md`
   （事项｜值｜说明 的表）。**拍板前不写任何正文。**

### 第 2 步：逐节生成（按指引模式路由，按范围选执行方式）

细则见 `references/section-writing.md`。路由规则与各模式的 docx 工具链：

- **素材修订**（默认模式）：素材先行五步——检索记块 id → 列使用计划 →
  `docx_section_create` 建节 → `docx_material_inject` 按块 id 整体保真注入底稿
  （段落/表格/图片零转写，docx 原件专属；非 docx 原件按文本参考自行撰写）→
  `docx_section_read` 拿段落序号 → `docx_section_revise` 定向修订适配本项目
  （旧项目名/公司名/参数按承诺清单改，全部落 Word 修订标记）；
- **格式跟随**：按招标文件规定的格式/表格逐项响应——依据节点来源 ID 回
  analysis 表取出处，再按行号读原文的格式要求，不自由发挥结构。**出处原件是
  docx 时优先 `docx_source_inject` 把格式原样拷进节文件**（source=来源文件名，
  lines=出处行号区间；独立格式附件留空 lines 整文件拷），再
  `docx_section_read` 拿段落序号与表格格坐标 → `docx_section_revise` 填空
  （表格空格子 fill、旧值 replace；我方信息按承诺清单填，未定值【待补：…】）；
  pdf 原件无可拷元素，维持内容一次成形于 `docx_section_create` 的 paragraphs
  （换行分段），微调走 revise；
- **推理撰写**：针对本项目写方案、不联网检索；全文一次成形于建节的
  paragraphs（换行分段），局部补充走 `docx_section_revise` 的 insert_after；

模板或附件填充的节执行期二分：**格式表格类（投标函/授权书/投标一览表等，
需按招标格式填写的）且出处原件是 docx → 建节后 `docx_source_inject` 整文件
拷原件 + revise 填空，产出节文件**（合册时按树序并进整本）；物理附件类
（资质证书复印件等，线下准备的）→ 登记到待填清单。目录容器跳过、待核验先问
用户。缺料标【待补：…】继续写不阻塞；分析阶段的待澄清项内联【待澄清：…】
（docx 节里同样用这两个内联标记，占位清点按 P 段号/表格 T 行号定位）。

执行方式按用户指定的范围分：

- **单节**：主线程就地写（写前浏览同层已写节的开头段，避免重复表达）；
- **多节（指定的章/节 ≥2）**：同一消息并发派发 `tender-body-writer` 子代理，
  一节一个。派发 description **必带清单（缺一不派）**，且按下列顺序排（共享
  内容在前、节差异在后——各子代理字节一致的共享前缀能命中模型供应商的前缀
  缓存，省真金白银）：第一行 ≤16 字短名（如「写 3.1 项目理解」，子代理卡片
  需要）→ **共享块**（任务目录前缀、**承诺清单全部值**——子代理不继承任务
  上下文，不传就会编）→ 差异块（节文件输出路径（.docx）、指引行（模式/依据
  ID/素材块 id）、要求出处行号区段、**格式跟随/格式件节的来源文件名**、
  兄弟节开头摘要（同层已写节各 2-3 句））；
- **整本（用户说全部/都写）**：按一级章节分批派发——一批返回、汇报进度、
  再派下一批（不做一次几十节的齐发）。

### 第 3 步：自查与全局比对

- 子代理逐节跑 validate_body（节路径 + block_ids；docx 节按接受全部修订后的
  终稿视角校验）；主线程对返回摘要里标记问题的节复查重跑；残留分级——
  **明确旧名（check_name_residue 的元数据级/显式名单）必须清零**，疑似提示
  （素材文件名来源，可能是通用产品术语）逐条核对：旧项目用语替换、确认通用
  则在收尾说明一句；
- 全部节完成后 `validate_body(section="body")` 跑全局承诺比对：承诺清单每个
  值未在任何正文出现会被点名（该节未写或值被改写，核对后补落或修正清单）；
- 占位/待澄清清单记录在案，收尾汇报用。

### 第 4 步：合册整本

全部节自查通过后调用 `docx_assemble_volume`（无参数）：按投标目录树序产出
每册一个 `work/body/整本-<册名>.docx`（一级章前分页、页脚页码、修订标记原样
保留）。返回里的缺失节/未并入文件逐条向用户点名。**整本是派生产物**——收尾
汇报要说明：改内容回节文件层改（或让模型改）再重新合册，直接手改整本会被
下次合册覆盖。

### 第 5 步：收尾汇报

- 逐条点名待澄清/待补清单（不可只字不提）；
- 汇报各节完成情况、未写节及原因、每册整本文件路径（引用
  check_pipeline_state 的 `[body]` 事实）；
- update_task_progress 更新任务进度便签（保持简短）。

## 注意事项

- 正文是干净文本：不带任何模型写的头部/元信息（建节只写标题与正文段）；
  【待补】【待澄清】是唯一允许的内联标记（评委要看的是干净文本）；
- 素材改写后必查残留（行业第一大事故=提交稿残留旧机构名/旧项目名）；
- 写一节前浏览同层已写节的开头段，避免跨节重复表达；
- 引用投标目录用 read_artifact（任务内当前版本），不猜文件路径；
- 表格单元格修订：`docx_section_revise` 按 table/row/col 定位（视图中 T 序号
  + R行C列 格坐标）——replace 改旧值、fill 填空格子；表格插行/删行与嵌套表格
  不支持（在 Word 中改）。
