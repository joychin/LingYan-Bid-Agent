# 逐节写作细则（素材先行）

## 素材修订（默认模式）

1. **检索**：按该节主题 search_references（写作素材库），记下命中的块 id；
2. **列使用计划**：动笔前列「本节用哪几块素材、各用在哪个部分」——把检索从
   「看过」变成「承诺」；计划里的块 id 即 validate_body 的 block_ids；
3. **贴底稿（元素级保真）**：`docx_section_create` 建节 → `docx_material_inject`
   按块 id 把素材整体注入（段落/表格连合并单元格/图片零转写，格式与样式随迁；
   仅 docx 原件可注入，非 docx 原件按文本参考自行撰写）；
4. **改写适配**：`docx_section_read` 读视图拿段落序号 → `docx_section_revise`
   定向修订（旧项目名/公司名/参数按本次承诺清单改，围绕本项目要求调整结构）；
   保住素材的结构与事实，替换项目相关信息——全部落成 Word 修订标记；
5. **自查**：validate_body 查素材使用率（重叠率过低=未实质使用）与疑似残留
   （素材文件名来源的旧名提示：旧项目用语替换，通用产品术语在汇报说明一句；
   元数据级旧名经 check_name_residue 扫，必须清零）。

教训（2026-09-06 实测）：不按此流程、凭自身知识自由发挥时，检索到的素材不会被
使用——质量显著下降；强制「以素材为底稿改写」后显著提升。**素材在场 ≠ 素材被用。**

## 格式跟随

按招标文件规定的格式/表格逐项响应：依据节点来源 ID → work/analysis 对应表行 →
出处列 → 按行号读 work/parse 原文取格式要求；不自由发挥结构。

- **出处原件是 docx → 拷原件优先**：`docx_section_create` 建节 →
  `docx_source_inject`（source=来源文件名，lines=出处行号区间；独立格式附件
  留空 lines 整文件拷）把招标格式原样拷进节文件——格式逐字节保真，表格/函件
  不会重排走样；→ `docx_section_read` 拿段落序号与表格格坐标 →
  `docx_section_revise` 填空适配（表格空格子 fill、旧值 replace；招标方信息
  保留、我方信息按承诺清单填，未定值【待补：…】）；
- pdf 原件无可拷元素 → 内容一次成形于 `docx_section_create` 的 paragraphs
  （换行分段），微调走 docx_section_revise。

## 推理撰写

针对本项目写方案（技术路线、实施步骤、保障措施）：

- 全文一次成形于 `docx_section_create` 的 paragraphs（换行分段）——不逐段
  insert_after 拼长文（多次小编辑既慢又易错位），局部补充才用 revise；
- 承诺类数字（工期/人员/服务/报价口径）只引「关键事实与承诺」清单值；
- 企业事实用 search_company_assets 取并可溯；拟投入承诺不是现状事实，数字一律
  重核。

## 通用纪律

- 缺料不阻塞：标【待补：…】继续写；分析阶段的待澄清项内联【待澄清：…】；
  两者收尾必须逐条点名；
- 正文不带模型写的头部/元信息（干净文本，评委要看的是干净文本）；
- 写节前浏览同层已写节的开头段（主线程就地写时），或对照任务描述里的兄弟节
  开头摘要（子代理派发时）——避免跨节重复表达；
- 一节写完即 validate_body 自查，不留到最后；
- 重写已存在的节：建节传 replace=true（旧版自动入恢复点栈），不要试图直接
  覆盖写。

## 子代理执行（多节并发）

并发派发的子代理（tender-body-writer）额外遵守：

- 承诺类数字只能用任务描述给出的承诺清单值——清单没有的写【待澄清：…】，
  不得编造（子代理不继承任务上下文，拿不到的信息一律标注带回，不猜）；
- 禁止改写 `work/body/写作指引.md` 与 `work/body/关键事实与承诺.md`（共享文件
  只归主线程维护——并发下这是唯一的写边界）；各自只写自己名分的节 .docx
  （重写已存在节传 replace=true）；
- 禁止调用 ask_human（无人应答），需要用户裁决的写【待澄清：…】带回；
- 完成返回摘要：节名、字数、使用素材块与重叠率、自查结果、待补/待澄清清单。

主线程派发时的排序纪律（SKILL 第 2 步）：短名 → 共享块（任务前缀+承诺清单）
→ 节差异——共享内容字节一致地放前面，各子代理才能共享更长的缓存前缀。
