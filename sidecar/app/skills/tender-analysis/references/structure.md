# 节：结构事实（structure）

只负责识别项目结构事实，输出 `work/analysis/structure.md`。

## 提取范围

从公告/邀请书/投标人须知前附表/正文前部定位：

| 字段 | 说明 |
|---|---|
| 项目名称 / 项目编号 | |
| 采购人（招标人）/ 代理机构 | |
| 招标方式 | 公开招标 / 邀请招标 / 竞争性谈判等 |
| 开标时间 / 开标地点 | 含讲标/演示/答疑安排（时间与地点原文有则必列） |
| 投标有效期 | 自何日起多少个日历日 |
| 投标语言 | 原文明确写语言要求时必列 |
| 截止时间类 | **必须区分**：投标/递交截止、澄清截止、开标时间、文件获取截止、报名截止、保证金到账截止、资格预审截止。**没有原文等同性不能互相补全**（不得拿开标时间填递交截止） |
| 包/标段/分册划分 | 有几个包/标段、名称编号、是否可分别投标、是否兼投兼中限制 |
| 文件间关系 | 承接第 0 步确认的来源集合与角色：主文件=用户指定；补充文件的角色（补遗/澄清/附录）按用户在问答中的说明或从内容判断，判断不了标 unknown 并登记澄清 |

**上表是字段超集**：基本信息表逐字段列行，原文没有的写值「未发现」+状态 unknown
（出处写已检查范围），**不得整行省略**——跨任务字段行集一致，下游消费与人工核对
才不漏项。

冲突（两处不一致）→ 状态 conflicting 并两列都写；判断不了 → unknown + 缺什么。

## 输出格式

```
## 一、项目基本信息
| 字段 | 值 | 状态 | 出处 |
|---|---|---|---|
| 项目名称 | … | 确认 | 招标文件.docx 招标公告（L4-L6） |
| 递交截止 | … | conflicting | 招标文件.docx 前附表（L91）/ 同文件 公告（L18-L20） |

## 二、标段/包划分
- 包1：…（编号、内容、是否单独递交）
（无分包时写一行：本项目不分包，整册投标）

## 三、文件间关系
- 招标文件.docx：正本
- 补遗文件.docx：补遗（依据：…）
（单文件时写一行：本次仅一份文件，无补遗/附件关系）

## 四、coverage 声明
已检查：公告、投标人须知前附表（outline 区段 …）；未检查：…
```

## 禁止

不提取联系人、预算金额、工期、技术方案内容、评分项、投标文件目录、正文。
