# 节：递交要求（requirements-submission）

只抽取影响**递交有效性**的明确规则。输出 `work/analysis/requirements-submission.md`。

## 提取范围

递交时间/方式/地点、签署盖章要求、电子文件处理（加密/平台上传）、份数与介质、
保证金或担保（金额/形式/退还）、投标有效期、以及原文明确写出的违反后果。

## 判定边界

- 「应、宜、建议、原则上、通常」**本身不等同于违反即无效**；只有原文明确为必须条件、
  或附带「不予受理、无效、否决、拒收」后果时，才在「高风险」列标「是」。
- 正本、副本、电子版、U 盘、加密件、封套是**递交实例/包装要求（delivery metadata）**，
  不得据此推断存在多个逻辑响应文件（响应文件划分由 tender-outline 按 format 节判断）。
- 不输出投标文件目录、章节、技术方案或内容分类。

## 输出格式

```
## 递交要求清单
| 序号 | 规则 | 高风险 | 后果 | 出处 |
|---|---|---|---|---|
| 1 | 递交截止：2026-09-10 09:30 | 是 | 逾期送达不予受理 | 招标文件.docx 招标公告 四（L141-L147） |
| 2 | 纸质正本一份、副本四份，均需密封 | 否 | — | 同文件 前附表 17（L257） |
（高风险=违反即无效/否决/拒收；后果原文不明确时「高风险=否、后果=—」；
出处每行都要带文件名或「同文件」标记，格式见 skills/_shared/evidence-rules.md）

## 待澄清登记
-（有则列，无则省略）

## coverage 声明
已检查：…；未检查：…
```
