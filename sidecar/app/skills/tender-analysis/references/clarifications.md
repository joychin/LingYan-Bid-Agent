# 节：待澄清汇总（clarifications）

把七节登记的待澄清项汇总为 `work/analysis/clarifications.md`。**只标注、不阻塞**——
不主动 ask_human 打断用户；未裁决项在下游可见（tender-outline 给相关节点挂 ⚠、
tender-body 在正文内联「【待澄清：…】」）。

## 只有以下情况才登记澄清（从严）

1. **两条可执行规则直接冲突**且没有明确优先级（如两处截止时间不一致）——
   须同时给出两处的出处；
2. 被引用的**关键内容不可获得**（附件缺失、区段不可读）且影响资格/递交/目录/正文；
3. **关键规则不足以确定**（unknown 且影响上述范围）。

普通未检索到（换个关键词或许能找到→先扩大检索，不是澄清）、行业惯例不熟悉、
一般性表述、不重要的附件——**不登记**。

## 登记格式

```
（第一行头部元信息注释）
## 待澄清清单
| 编号 | 类型 | 问题 | 影响范围 | 建议动作 |
|---|---|---|---|---|
| CLAR-01 | 冲突 | 递交截止时间两处不一致（公告 09:00 / 须知 09:30） | 递交、目录 | 向招标代理确认 |

（编号 CLAR-01 起两位零填充递增；类型枚举：冲突/缺失/歧义）

## 状态
未裁决 0 条（用户在对话中补充答复后，把对应行标为已裁决并附答复摘要）
```

## 维护规则

- 单项重跑某节后，同步更新本清单中该节来源的条目（其余不动）。
- 用户在对话中给出裁决 → 对应条目标「已裁决：…」；已裁决条目保留不删（下游可追溯）。
