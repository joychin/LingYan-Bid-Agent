从招标文件到合册交付

三个阶段，五步交付。

阶段 1 · 读原文 01

把招标文件读成结构化数据

解析 PDF / Word / 扫描件，提取章节、关键要求和评分办法，落到能引用的工作区。

  • 第 1 步

    解析招标文件。数字版 PDF 读书签和目录链接，扫描件走云端 OCR，章节结构和页码锚点全部落盘。

  • 第 2 步

    提取要点。资格条件、工期、评分办法逐项登记，每条注明出自原文哪一页、哪一行，引用行号经程序校验。

阶段 2 · 搭架子写正文 02

照评分办法搭目录，逐节写正文

目录按评分项组织，每一节先定交付形态；写作时用你的素材库和知识库，缺什么提前列清楚。

  • 第 3 步

    生成目录。照评分办法搭目录，每一节写什么、用什么素材、缺什么材料，先列成一张指引表给你确认。

  • 第 4 步

    逐节写正文。多路并发逐节写：历史标书素材改写复用，格式件照招标原件拷贝；拿不准的事先问你，缺料标【待补】不编造。

阶段 3 · 合册交付 03

合成整本 Word，等你最后审一遍

按目录合成整本 .docx，标书版式（封面 / 标题分级 / 页码 / 表格）一并排好；AI 修改走修订标记，你逐条审。

  • 第 5 步

    合册交付。没写完的地方留批注、不留正文，打印和 PDF 导出不会带出去；审完就是能交的稿子。

标书写得快，也要靠得住

快靠模型。靠得住，靠的是下面三件事。

每个结论都有出处

每个要求都跟着招标原文

正文里的数字和结论，后面都跟着原文的章节、行号和页码；引用行号经过程序校验，超出原文范围会被直接拦下。评审对照、自己审核，点一下就能回到原文那一段。

常见问题

关于区别、模型、联网和交付格式的实际问题。

和直接用 ChatGPT 写标书有什么区别？

通用对话模型直接给你一段文字，数字对不对、要求漏没漏，没人兜底。灵燕智能的每条要求都注明原文出处并经程序校验，大事先问你拍板，最终交付的是按标书版式排好的整本 Word——过程可审计，结果能直接用。

需要联网才能用吗？

解析、存储、正文生成、Word 合成都在你电脑上完成。需要联网的只有两类事：调用你自己配置的大模型，以及（可选）把扫描件交给云端 OCR 识别。

用什么大模型？

自带 API Key，支持 DeepSeek、智谱、Kimi、通义等 OpenAI 兼容接口；可以配置多个模型，按对话随时切换。

支持哪些操作系统？

目前提供 Windows 与 macOS 安装包，可在 GitHub Releases 页面下载。

生成结果是 Word 吗？我能修改吗？

是标准 .docx。AI 的修改以修订标记进入正文，在 Word 里逐条接受或拒绝；你手改过的内容，后续章节写作会参考。应用内也能直接预览版式，文件不出本机。
